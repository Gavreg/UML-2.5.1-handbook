# Project overview

Разработка интерактвного справочника по UML 2.5.1 на основе официальных спецификаций  https://www.omg.org/spec/UML/2.5.1/About-UML

Пример похожего проекта, но для Latex https://github.com/Gavreg/Latex3-handbook.github.io

#Цель

Облегчить изучение метамодели UML, предоставив пользователям удобный интерактивный вариант этой спецификации на русском языке.

## Technology stack and architecture

Справочник является локальным сайтом, построенным на HTML и JS. Допускается использование других технологий. КЛючевое требование, что он должен работать и онлайн и офлайнв любом совремнном браузере.

### Текущая реализация

- `site/index.html` — точка входа статического SPA с hash-маршрутами.
- `site/app.js` — навигация, поиск, маршрутизация, мобильное меню и цветовые темы.
- `site/styles.css` — адаптивное оформление без внешних шрифтов и библиотек.
- `site/data/common-structure.js` — русские описания раздела 7 и данные для локальной работы через `file://` без `fetch`.
- `site/data/common-structure-xmi.js` — генерируемые из XMI собственные и унаследованные атрибуты, включая обе стороны всех ассоциаций метамодели.
- `site/assets/diagrams/` — 21 PNG-скриншот рисунков спецификации; рисунок 7.1 также перерисован в интерактивный SVG со ссылками классов.
- `docs/` — официальные PDF и XMI OMG, извлечённые текстовые материалы.
- `scripts/render_common_structure_diagrams.py` — повторное создание скриншотов из PDF; требует PyMuPDF.
- `scripts/sync_xmi_properties.py` — генерация и проверка свойств по нормативному XMI; русские описания отсутствующих свойств задаются в самом скрипте.
- `scripts/validate_site.py` — статическая проверка, контроль синхронизации с XMI и проверка всех маршрутов через локальный Chrome или Edge.

### Команды проверки

```bash
python scripts/sync_xmi_properties.py
python scripts/sync_xmi_properties.py --check
python scripts/validate_site.py
python scripts/render_common_structure_diagrams.py
```

Проверка сайта не требует запуска HTTP-сервера: открывать `site/index.html` непосредственно в браузере.

#Требования

Справочник должен быть на русском языке

Структура справочника должна совпадать с структурой pdf спецификации UML 2 5 1.

Каждому объекту метамодели должна соотвестовать страница справочника с описанием и определением.   

Диаграммы классов должны быть интерактивными, классы на них - должны быть ссылками на разделы с соответсвующими определниями.

Диаграммы должны быть веторними и по стилю  и виду элементов совпадать с теми, что в спецификации.

необходимые скрипты для создания и редактирования справочника складывай в scripts. в кадлый скрипт включай метаинформацию о нем, его интерфейс, назначение и цель.

если требование в чате не коректно или абстрактно - задавай уточняющие вопросы.

## Правила наполнения справочника

- Единственные нормативные источники содержимого — официальная спецификация
  OMG UML 2.5.1 из `docs/omg-uml-2.5.1-formal-17-12-05.pdf` и её XMI-модель
  `docs/UML-2.5.1.xmi`.
- Атрибуты классов и концы ассоциаций сверять с XMI. На страницах классов
  показывать все обычные атрибуты, обе стороны всех ассоциаций метамодели и
  унаследованные свойства; не ограничиваться свойствами внутри прямоугольника
  класса или ассоциациями текущего раздела диаграммы.
- Не выдумывать определения и не дополнять спецификацию сведениями из других
  источников без явного указания.
- Для каждого раздела сохранять исходную нумерацию спецификации.
- Русские названия сопровождать оригинальными английскими именами элементов
  метамодели. Имена классов, свойств, ассоциаций и перечислений не переводить
  в программных идентификаторах и подписях, если это может нарушить
  соответствие спецификации.
- Для переводимых терминов использовать единый глоссарий. Не использовать
  разные русские переводы для одного термина без необходимости.
- На странице элемента метамодели указывать:
  - русское и английское название;
  - определение и описание;
  - номер раздела спецификации;
  - родительские и наследуемые элементы, если они есть;
  - атрибуты, ассоциации, ограничения и семантику, если они описаны;
  - ссылки на связанные элементы и диаграммы.
- Не считать страницу готовой, если она содержит только машинный перевод
  без проверки структуры, ссылок и терминологии.

## Технические ограничения сайта

- Точка входа: `site/index.html`.
- Сайт должен открываться не только через HTTP-сервер, но и непосредственно
  из локальной файловой системы по двойному щелчку.
- Не использовать CDN, внешние шрифты, удалённые скрипты и другие ресурсы,
  необходимые для основной работы сайта.
- Учитывать ограничения протокола `file://`: не полагаться на загрузку локальных
  данных через `fetch`, если это препятствует автономному открытию сайта.
- Основная навигация и содержание должны работать без серверной части.
- Все ссылки между страницами и элементами диаграмм должны быть относительными.

## Диаграммы

- Новые диаграммы создавать в SVG.
- Сохранять нотацию, расположение основных элементов и оформление диаграмм
  спецификации, насколько это позволяет интерактивная реализация.
- Названия классов на диаграммах должны быть ссылками на соответствующие
  страницы справочника.
- Диаграммы должны масштабироваться без потери читаемости и качества.
- Нельзя считать скриншот диаграммы выполнением требования интерактивности.
- Скриншоты допускаются только как временное решение текущего этапа.

## Проверка результата

Перед завершением изменений проверить:

- открытие `site/index.html` локально без запуска сервера;
- отсутствие ошибок JavaScript в консоли браузера;
- работу навигации, поиска и интерактивных диаграмм, если они затронуты;
- отсутствие неработающих внутренних ссылок;
- соответствие структуры и нумерации спецификации;
- корректное отображение русского текста;
- наличие обязательных ссылок и сведений о лицензии в подвале.
